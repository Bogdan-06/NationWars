# Nation Wars 0.5.0 manual acceptance checklist

Use a disposable multiplayer test world and keep a copy of its `world/data`
folder. Several checks deliberately delete or annex nations. Unless a check
says otherwise, use nation owners and keep `Puppets=true`.

## Build and packaging

- [ ] Run `gradlew clean build`; it exits successfully without using stale
  build output.
- [ ] Confirm every automated test passes in the clean build.
- [ ] Open the generated JAR and confirm `assets/nationwars/lang/en_us.json`,
  `ro_ro.json`, `es_es.json`, and `pl_pl.json` are present.
- [ ] Confirm all four language catalogs parse and have identical key sets and
  placeholders.
- [ ] Start the dedicated-server configuration and wait for the normal `Done`
  message with Nation Wars 0.5.0 and OPAC loaded.
- [ ] Confirm the server log has no Nation Wars exception during load,
  normalization, OPAC synchronization, income, or maintenance ticks.

## Command registration and configuration

- [ ] As permission level 2, `/configure` displays every setting and includes
  `Puppets: true` on a new/default configuration.
- [ ] `/configure Puppets false` persists `false`; `/configure Puppets true`
  persists `true` after a server restart.
- [ ] `/configurate` is unknown and absent from command suggestions.
- [ ] `/configure Satelites true` is unknown and absent from suggestions.
- [ ] `/configure Satellites true` still works and controls named
  `/nation info <name>`.
- [ ] `/nations` is unknown and absent from command suggestions.
- [ ] `/nation create` opens the doctrine menu and, after selection, accepts the
  nation name through the established chat-name flow.
- [ ] `/nation create Test USA` is rejected as invalid syntax and does not
  create a nation.
- [ ] A permission-level-4 operator can see `/nwdev`, `/nationwarsdev`, and
  `/configure deletenation` in suggestions even when debug commands are
  disabled.
- [ ] With `debugCommandsEnabled=false`, every destructive debug handler
  returns the translated disabled message and makes no change; `/configure
  deletenation` remains available because it is an operator configuration
  command rather than a development command.
- [ ] A non-level-4 player cannot see or run `/configure deletenation`.
- [ ] `/configure deletenation <country>` accepts a full display name or stored
  ID, removes the requested nation, releases its claims/members and puppet
  references, resynchronizes OPAC/display names, and writes an executor/target
  audit entry.

## Nation information and creation regression

- [ ] `/nation info` reports the owner's capital as the correct dimension and
  chunk coordinates.
- [ ] `/nation info <name>` reports that nation's capital when `Satellites=true`.
- [ ] A malformed/missing capital is displayed with the translated none value
  rather than crashing the command.
- [ ] A new nation still starts with $250 treasury and its owner still has the
  established $50 starting player balance.
- [ ] New nations still default to `INVITE_ONLY`; invitation expiry and
  join-policy commands behave as in 0.4.0.

## Passive income formula

- [ ] An unupgraded, one-member non-Soviet nation with 1.0 income multiplier
  receives exactly $120 after one ten-minute cycle.
- [ ] The same nation with four members receives exactly $144: `$120 + 3*$8`.
- [ ] Each additional member beyond the first adds exactly $8; zero/one member
  never produces a negative member term.
- [ ] A doctrine datapack multiplier changes the active capital/structure term
  but does not multiply the $8 member term.
- [ ] A non-USA upgrade adds the unchanged $6 before the doctrine multiplier.
- [ ] A paralyzed capital contributes no capital/upgrade income, while active
  structures and additional-member income continue according to their own
  state.
- [ ] Passive income runs every 12,000 ticks (normally ten minutes) and no extra
  or delayed save cycle was introduced.
- [ ] `/nation info` reports the exact current ten-minute payout, including
  member, doctrine, upgrade, structure, and active paralysis effects.
- [ ] Recurring nation-trade payments are still limited to generated income and
  conserve money after cent rounding.

## Scorched Earth claim protection

- [ ] With `ScorchedEarth=false`, OPAC protection still blocks hostile block
  breaking, placing, fluid use, container use, entity interaction/attacks, and
  player-caused explosions inside an enemy war claim.
- [ ] With `ScorchedEarth=true` during an active enemy war, those same hostile
  actions receive the temporary OPAC bypass and no paid-access prompt appears.
- [ ] `ScorchedEarth=true` does not bypass protection in neutral territory or
  territory owned by a nation outside the active war.
- [ ] A pending peace offer and the established post-respawn lock still pause
  hostile actions; enemy beds remain protected by the explicit war rule.

## Doctrine and general-rule changes

- [ ] Soviet, one member, zero upgrades: passive income is $0.
- [ ] Soviet, four members, zero upgrades: passive income is $24.
- [ ] Soviet, four members, one upgrade: passive income is $30, proving both
  upgrade and member income still work.
- [ ] One active USA city contributes 0.2x current capital income ($24 at the
  $120 capital baseline), not the old fixed $3 or 0.25x amount.
- [ ] Creating a USA city still charges that claim's current claim cost.
- [ ] One active British coast claim contributes 0.1x current capital income
  ($12 at the $120 baseline), including when the capital itself is coastal.
- [ ] A paralyzed USA city or British coast claim contributes no structure
  income for that cycle.
- [ ] An eligible Italian building reward pays exactly $2 when the unchanged
  20% roll succeeds; rate limits and position tracking remain unchanged.
- [ ] Italy's doctrine text says `Kingdom of the South`, not `Civil War`, in
  English, Romanian, Spanish, and Polish.
- [ ] An Italian attacker recapturing one of its war-start core claims receives
  exactly +10 seconds to the calculated capture requirement.
- [ ] An Italian attacker recapturing captured land that was not in its
  war-start core snapshot does not receive that +10 seconds.
- [ ] Push-over lets a defender with more claims reject an Italian declaration
  once and does not allow a second rejection for the persisted pair.
- [ ] Declining a valid allied/guaranteed defense call costs $250; France costs
  $750, including the existing negative-treasury edge case.
- [ ] France pays 1.5x maintenance only while it is the primary attacker in an
  active war, not while defending.
- [ ] Soviet market buyers pay 1.25x the listing price.
- [ ] Soviet defended land takes 2x capture time with fewer than two attacking
  players and normal calculated time with two or more.
- [ ] Each distinct lost Romanian war-start core adds +0.1 to maintenance and
  the effect stacks; losing a non-core does not add it.

## Puppet creation, proposals, and configuration gate

- [ ] `/puppet` is owner-only and shows independent status for an unrelated
  nation; a non-owner member receives the owner-only error.
- [ ] `/puppet propose <country>` creates a pending proposal and notifies the
  target owner; duplicate/self/invalid proposals fail without state changes.
- [ ] `/puppet accept <master>` establishes the relation at exactly 100 points
  and notifies both nations.
- [ ] `/puppet reject <master>` removes the proposal and notifies both nations.
- [ ] Accept/reject with no matching proposal fails and does not create a
  relation.
- [ ] A voluntary proposal fails if either nation is in an active war.
- [ ] One master can control two or more direct puppets.
- [ ] A puppet cannot acquire a second master, but may later acquire direct
  puppets of its own when that creates no cycle; all cycle attempts fail.
- [ ] If a country with direct puppets becomes a puppet through an allowed
  peace/proposal flow, all of its direct puppets become independent.
- [ ] With `Puppets=false`, `/puppet` actions return disabled, the Puppet peace
  term is hidden, puppet tax/restrictions/point effects stop, and the saved
  relation still exists after re-enabling the option.
- [ ] While disabled, the persisted relation does not block an otherwise valid
  normal claim or war declaration.
- [ ] If Puppets is disabled after an independence war starts, the existing war
  can still resolve cleanly through peace, surrender, or capital capture.

## Puppet point thresholds and cooldowns

- [ ] A puppet at 0 points cannot claim, start a war, or liberate; its master
  can annex it.
- [ ] At 1-49 points it cannot claim, war, liberate, or be annexed solely by
  points.
- [ ] At 50-150 points it can claim but cannot start an independence war or
  liberate.
- [ ] At exactly 150, `/puppet war` fails; at 151 it may start when other war
  preconditions are met.
- [ ] At 151-199 it can claim and start an independence war but cannot use
  peaceful liberation.
- [ ] At 200 it can claim, start an independence war, and manually liberate;
  its master cannot annex solely by points.
- [ ] Reaching 0 does not auto-annex; reaching 200 does not auto-release.
- [ ] `/puppet agitate` adds exactly 10, clamps at 200, and cannot be used again
  until its 600-second deadline.
- [ ] `/puppet pacify <country>` removes exactly 10, clamps at 0, and cannot be
  used again on that relation until its 600-second deadline.
- [ ] Agitate and pacify use their separate cooldown fields, survive restart,
  and become usable at the exact persisted deadline.
- [ ] `/puppet liberate` and `/puppet automate` perform the same 200-point
  release; both fail below 200.
- [ ] All point-changing commands fail while that puppet is in an independence
  war.

## Trade-derived points

- [ ] The first accepted trade between a puppet and a foreign nation adds one
  independence point.
- [ ] A second qualifying foreign trade inside 120 seconds still completes but
  does not change points.
- [ ] A qualifying trade at/after the 120-second deadline adds one again.
- [ ] Rejecting an incoming master trade offer adds one point and starts the
  same 120-second throttle.
- [ ] Rejecting another master offer during the throttle still rejects the
  offer but does not change points.
- [ ] A one-sided master gift where the puppet receives positive money, claim,
  or recurring income and gives none removes one point.
- [ ] A bilateral master/puppet trade, an empty exchange, or a deal favoring the
  master does not trigger the one-point reduction.
- [ ] Accepted/rejected trade effects share one throttle per puppet rather than
  separate cooldowns.
- [ ] No accepted or rejected trade changes points during an independence war.
- [ ] Trade point cooldowns and current points survive a server restart.

## Puppet passive-income tax

- [ ] With no trade obligations, a puppet generating $120 retains $96 and its
  master receives $24 in the same income cycle.
- [ ] A four-member puppet generating $144 retains $115.20 and its master
  receives $28.80, proving member income is taxable.
- [ ] Tax is rounded to cents and total treasury change is conserved.
- [ ] Puppet tax is removed before recurring trade obligations. For $120 gross
  and a $100 obligation, tax is $24 and no more than the remaining $96 is
  diverted.
- [ ] A master with multiple puppets receives the rounded tax from each in
  addition to its own normal income.
- [ ] In a valid multi-level relation, each puppet pays on its own generated
  income only; puppet tax received from below is not taxed again upstream.
- [ ] `Puppets=false` stops tax entirely without removing the relation; turning
  it back on resumes tax.

## Puppet peace term and lifecycle

- [ ] In a normal war with `Puppets=true`, the proposer can toggle the Puppet
  term in peace slot 50 and the receiver sees it read-only.
- [ ] Accepting that offer makes the receiver the proposer's puppet at 100
  points after revalidation.
- [ ] The term cannot be sent if it would create an invalid/cyclic relation or
  if puppets were disabled after the menu opened.
- [ ] Independence-war peace screens do not offer the ordinary Puppet term.
- [ ] `/puppet release <country>` removes a direct relation without transferring
  claims, treasury, or members.
- [ ] `/puppet release` during that puppet's active independence war fails and
  leaves both relation and war intact.
- [ ] `/puppet annex` fails at points 1-200 with fewer than three losses and
  fails while the master or puppet is in an active war.
- [ ] Annexing at 0 points succeeds; annexing after three losses succeeds
  regardless of remaining points.
- [ ] Annexation transfers every puppet claim, non-negative treasury amount,
  and member mapping to the master, then removes the puppet nation.
- [ ] Annexation does not transfer or erase members' personal money balances.
- [ ] The annexed nation's direct puppets are released and notified.
- [ ] OPAC ownership and map/display names show the master after annexed claims
  transfer; no orphaned Nation Wars or OPAC claims remain.
- [ ] Deleting a master through `/configure deletenation` releases its puppets;
  deleting a puppet removes its relation and all related proposals.

## Independence-war outcomes

- [ ] `/puppet war` requires an owner, an active master relation, 151-200
  points, fewer than three prior losses, and both nations free of other wars.
- [ ] Starting it creates an immediate active war with the puppet attacking its
  master; no ordinary justification or defense-call flow leaks in.
- [ ] Third nations cannot request/accept a voluntary join or be added through
  an alliance/guarantee defense call in an independence war.
- [ ] A puppet cannot justify/declare a normal war on any nation while puppets
  are enabled, and a master cannot justify/declare against its direct puppet.
- [ ] An unrelated nation can still attack a puppet subject to all ordinary war
  checks; `Puppets=false` suspends the puppet-specific declaration blocks.
- [ ] Independence points and trade effects remain frozen for the entire
  independence war.
- [ ] A peace offer sent by the puppet and accepted by the master produces a
  puppet victory and releases the puppet.
- [ ] A peace offer sent by the master and accepted by the puppet produces a
  puppet loss, subtracts 50 points, and records one loss.
- [ ] Master surrender produces a puppet victory; puppet surrender produces a
  puppet loss.
- [ ] Capturing the master's capital or last claim produces a puppet victory;
  capturing the puppet's capital or last claim produces a puppet loss.
- [ ] Every resolution restores all captured claims to original owners and
  performs OPAC synchronization.
- [ ] Selected peace claims/money, ordinary surrender shares, capitulation land,
  treasury transfers, and elimination do not apply to independence-war results.
- [ ] A loss clamps points at 0, increments the loss count once, removes the war,
  and leaves the master/puppet relation active.
- [ ] After the third loss, `/puppet war` refuses a fourth attempt and the
  master can annex even if points are above 0.
- [ ] A puppet victory removes the relation and war without changing personal
  player balances or granting master territory.

  preserved through migration and the result saves as data version 2.
- [ ] Load a version-1 save: it gains empty/default puppet collections and saves
  as data version 2 without changing existing values.
- [ ] Reload a version-2 save with relations, proposal, points, losses, and all
  cooldowns; every value survives exactly.
- [ ] Corrupt/missing puppet references are reported and removed without losing
  valid nations or unrelated state.
- [ ] Existing `.tmp`, `.bak`, corrupt-main recovery, and pre-migration backup
  behavior still passes its regression tests.
- [ ] English, Romanian, Spanish, and Polish clients each see localized puppet command,
  peace-menu, doctrine, warning, and error text while nation/player names stay
  unchanged.
- [ ] A client without Nation Wars resources demonstrates the documented
  fallback limitation; a client with the JAR follows its Minecraft language.
- [ ] Ordinary market, espionage, alliance, guarantee, truce, normal peace,
  capture, surrender, claim, maintenance, and OPAC regression tests still pass.
- [ ] Compare the source tree against the 0.4.0 copy and confirm no unrelated
  large/binary files were rewritten.
